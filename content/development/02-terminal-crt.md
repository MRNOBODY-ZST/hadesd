把博客画成终端很容易：深色背景、等宽字体、一个闪烁光标就能建立印象。难的是让它仍然像网页一样可用：链接能点击，文字能选择，中文输入法正常工作，长文章能滚动，显卡不可用时还能读。

HADESD 的做法是保留真实 DOM 作为交互来源，再把可见内容转换成 CRT 所需的图形信号。终端命令和图形效果是两层独立能力，任何一层都不应成为正文的唯一入口。

## 先定义“文件”究竟是什么

这里的终端没有连接宿主机 Shell。它操作的是由公开内容索引生成的虚拟文件系统。

一篇文章同时具有内容 ID、公开路由和虚拟路径。例如 `/posts/example` 是可分享的网页地址，`~/posts/example.md` 是终端里的访问方式。虚拟节点保留原始 `contentId` 与 `route`，目录别名不复制真实文章。

游客的家目录为 `/home/guest`，登录后可以显示自己的家目录。这个路径表达浏览器会话里的导航位置，不对应服务器磁盘上的同名目录。

`createVfs` 负责生成节点，路径规范化与目标解析负责处理 `.`、`..`、`~` 等语义。把这些逻辑放在 `packages/terminal-core` 中，React 组件就不必同时承担命令解析、目录规则和键盘布局。

## 解释器返回结果，网页决定怎么展示

命令执行时，解释器拿到一个上下文：当前目录、用户名、历史记录、节点列表、读文件回调、导航回调和显示设置回调。

它返回的是结构化输出，而不是直接操作页面。常见输出包括普通文本、错误、Markdown、文件缓冲区和导航结果。这个边界允许相同的命令规则通过单元测试验证，也让网页层单独处理焦点、滚动和异步请求。

例如，在存在相应文章的站点中，可以这样阅读：

```text
ls
cd posts
ls
open example.md
cat example.md
```

`open` 在终端历史中渲染 Markdown，`cat` 输出原始正文，`cd` 更新虚拟目录。直接点击文章链接则仍然可以进入独立网页地址。两种入口访问同一份公开内容，但不会强迫每条命令都引发页面跳转。

解释器支持引号、转义和有限的公开环境变量，例如 `$USER`、`$PWD`。管道、重定向、串联命令和命令替换不在当前实现范围内，解析器会拒绝这些语法。它没有调用系统 Shell，也不会把输入拼接成服务器命令。

## 账号交互需要自己的状态

`login`、`register`、`passwd` 等命令不是简单的一行字符串运算。它们需要逐步提示、密码输入、取消和异步 API 请求，因此网页层使用专门的账号交互流程处理。

密码提示使用隐藏输入框。历史记录对敏感账号命令参数脱敏，交互中的密码不应送入普通命令历史。用户退出或账号身份变化后，私有输出也有清理逻辑。

Vim 风格缓冲区同样需要分清权限：管理员可以读取和保存服务器草稿；普通读者编辑的是浏览器本地副本。外观上都能输入 `:w`，实际保存位置由账号能力决定。服务端权限检查仍是最终边界。

## 长文章首先是一个滚动问题

终端历史需要处理一组互相牵制的目标：新命令输出要能被发现，长正文要从开头读，用户正在回看旧内容时又不能被新状态强行拉到底部。

当前界面使用真实滚动容器，记录每次输出的位置，并区分“跟随末尾”和“查看历史”。鼠标滚轮、触屏、滚动条与 PageUp / PageDown 作用于终端区域。页面整体的固定视口，不等于正文不能自然滚动。

中文输入法也不能被当成普通按键。组合输入期间的 Enter、方向键和光标移动，需要与命令提交和历史切换区别对待。一个终端如果只在英文输入和短输出下成立，还没有完成基本交互。

## DOM 是唯一的布局与交互依据

CRT 模式没有另造一套只在 Canvas 中存在的文章。真实链接、输入框、文本选择和语义节点仍由 DOM 提供。

`terminalTexture.ts` 会测量可见 DOM 的文字和元素位置，把终端内容绘制到二维 Canvas，再作为纹理送入 Three.js。它针对当前终端实现，并不是能够完整复刻任意网页 CSS 的截图器；渐变、复杂滤镜和任意三维 CSS 变换都不在其通用承诺范围内。

更新也不是无条件每帧遍历整篇文章。内容变化、元素尺寸变化、输入、滚动、选择和字体加载会使纹理失效，随后合并到动画帧中刷新。可见字符、元素数和纹理尺寸都有上限，避免长文把每次重绘变成无界工作。

一个重要细节是：屏幕外的文字不应该提前吃完可见字符预算。否则长篇 `cat` 输出滚到后半段时，Canvas 可能没有额度再绘制眼前的文字，DOM 明明存在，屏幕却像丢失了正文。

## 图形效果不能改变点击目标

渲染管线以文字纹理为输入，再叠加扫描线、辉光、暗角等显示效果。Three.js 的 `WebGPURenderer` 支持 WebGPU 与 WebGL2 后端，React Three Fiber 负责场景组件组织。

阅读界面还有一个与普通三维场景不同的约束：屏幕上的字必须与真实 DOM 的点击、光标和选择位置保持一致。色散或几何扰动如果过强，视觉上看到的链接会偏离实际命中区域，最终变成“好看但点不准”。

因此，开场场景与稳定阅读界面不能使用完全相同的效果强度。前者可以强调空间和过渡，后者优先保证字符边缘与交互位置清楚。

跨域图片还有 Canvas 污染问题。当前实现提供原生图片叠层，让不适合进入纹理的图片继续由浏览器绘制，并按终端区域裁剪。这样无需为了一个显示效果去假设所有图片服务器都会提供跨域读取许可。

## 把片头写成状态机

片头不是一个从 0 到 100 的统一计时器。当前时间线包含以下阶段：

```text
boot → pullback → hero → journey → resume → penetrate → reveal → terminal
```

开机、拉远、续启、穿屏和逐批显字由时间驱动；介绍画面和旅程主要由用户滚动、触屏或键盘推进。用户停下来时，旅程就应该停下来。

这一区分能避免一个常见问题：三维进度已经抵达终点，终端输入却在内容建立之前提前解锁。真正可交互的状态是 `terminal`，而不只是“滚动值达到 1”。

跨阶段渲染还要读取同一个时钟来源。React 状态提交与图形帧并不完全同步，若图形帧把上一阶段名称与下一阶段的零进度混在一起，就可能出现短暂回闪。代码使用共享阶段引用与对应进度，让一帧内的判断来自一致状态。

## 回退路径是功能的一部分

关闭 CRT、开启专注阅读、系统要求减少动态效果，或者 GPU 初始化失败时，终端都需要可达的原生显示路径。无 JavaScript 和打印模式也有独立的样式处理，不能依赖交互动画结束才显示正文。

验证这套界面时，应分别观察命令逻辑、DOM 交互和真实像素：路径补全测试不能证明扫描线效果正确，截图也不能证明退出后没有保留私有记录。资源清理、窗口缩放、手机输入和长文滚动都值得单独检查。

一个可靠的复古终端，应该先是一份可以阅读和操作的网页，然后才是一台看起来像旧电脑的网页。

## 对照源码阅读

- `packages/terminal-core/src/index.ts`：词法解析、虚拟路径、补全与结构化输出。
- `apps/web/app/shell/Terminal.tsx`：输入、历史、滚动、异步取消与输出呈现。
- `apps/web/app/community/terminalAccount.ts`：账号命令的交互流程。
- `apps/web/app/effects/three/terminalTexture.ts`：DOM 到 Canvas 的文字绘制。
- `apps/web/app/effects/three/TerminalScene.tsx`：纹理、场景与渲染后端。
- `apps/web/app/effects/timeline.ts`：片头阶段与进度函数。
- `apps/web/app/effects/NativeImageLayer.tsx`：原生图片叠层。
