## 初版架构记录

- 2026-09-09：采用用户 daemon 的 Spring Boot 4.1.1、Java25、Gradle9.7.1，不迁移 Maven。移除无需求 MongoDB、阻塞 Redis/JPA；数据库使用 R2DBC，Redis 使用响应式客户端。
- Flyway JDBC 仅作为启动迁移使用，不进入 WebFlux 请求路径。密码散列和必需的文件特征检查隔离到 boundedElastic。
- 用户授权完整本地实现与验证。文档内针对架构的建议经本次用户 Reactive 指令修正。无真实生产部署。
- 官方资料核对：[React Router 静态预渲染](https://reactrouter.com/how-to/pre-rendering)、[WebFlux CSRF](https://docs.spring.io/spring-security/reference/reactive/exploits/csrf.html)、[Boot要求](https://docs.spring.io/spring-boot/system-requirements.html)、[MySQL ngram](https://dev.mysql.com/doc/refman/8.4/en/fulltext-search-ngram.html)。

- 前端版本固定为 React 19.2.8、React Router Framework 8.3.1、Vite 8.2.2、TypeScript 7.0.2，pnpm 11.19.0，提交完整锁文件。公开页面静态预渲染，后台独立 SPA；生产无 Node SSR 服务。
- 内容修订同时冻结标题、slug、标签、摘要、语言及封面。标签存于修订 JSON，`release_entry` 同时作为当前发布内容关联与 MySQL ngram 搜索投影；不为尚无需求的标签管理增加重复事实表。
- `current/manifest.json` 是可见版本权威。后端只能读发布目录，Worker 才能构建、校验和原子切换。`SETTINGS` 是显式发布操作，防止后台保存配置直接改变公开站点。
- 保留当前及前 5 个历史发布版本；对应附件由不可变修订及保留版本引用保护。过期正文目录清理，hash 代码资源保留以支持旧标签页。
- Vite 预渲染固定 IPv4 loopback，并规范化预渲染请求的尾斜杠与 Unicode 路径。布局水合回归直接执行 SSR→hydrate，不使用 suppression。
- 本地恢复演练使用独立临时数据库，不覆盖运行库。故障演练仅操作本任务的本地依赖容器，并自动恢复。外部 DNS、TLS 证书、CDN 清理与真实云账号不属于本次本地验证结果。
- S3 适配器以真实 MinIO 测试 Get/Put/Delete 与流式读取；没有把协议兼容测试表述成 AWS 生产 bucket 联通。Headless Chromium 的 SwiftShader 结果只证明功能及调用调度，不代表物理 GPU 性能。

## 2026-09-09：固定视口终端与三维 CRT（v2，历史）

- 用户追加要求明确覆盖原附件及 v1 的可滚动 DOM 工作站、无专门启动动画和 Low 默认：公开界面改为固定视口终端，鼠标滚轮不推动页面，长文与命令输出用整屏分页；默认 Full CRT，并加入可跳过、可重放的飞出屏幕启动场景。
- 保留 DOM 作为布局、链接、输入、选择与语义来源，显示时将真实终端文字送入 GPU 纹理。固定视口是正常 JavaScript 交互方式；No-JS、打印和 GPU 失败有各自回退，未删除静态正文、SEO 与独立内容 URL。
- 采用 Three.js 0.186.0、React Three Fiber 9.7.0、Three Shading Language，以及同一 WebGPURenderer 的 WebGPU / WebGL2 后端。文字 RT 与场景 RT 构成主管线，bloom 保留其内部处理通道。新版需要真实场景/文字采样，不再沿用透明 WebGL 扫描线覆盖层。
- `reboot` 重放约 5.6 秒的启动，`display` 调整显示；专注阅读仍在固定终端中分页。v2 偏好使用新的 `hadesd.display.v2`，不自动继承旧 Low 默认。减少动态效果跳过飞行，Off 使用原生文字；Low 的 demand / 约 2Hz 光标刷新与 v1 的零闲置 RAF 定义不同。
- Shader Sweden / Skyworks 作为用户指定的视觉方向参考；本站飞行器几何、灯光、动画和 shader 自主实现，不复制参考项目的模型、贴图或代码资源。
- 保留原公开站说明为 `web-v1-notes.md`。v1 的 50 单测、10 E2E 和约 113 KiB 首页 JS 是历史验收，不能作为 v2 通过证据。v2 重新执行类型检查、单测、生产浏览器、GPU 后端与性能验证。

## 2026-09-09：用户纠正优先，个人计算机主题（v3，历史）

- 用户进一步明确所需叙事是 DOS 蓝色 CRT 开机、左侧介绍与右侧复古 Mac、滚动推近屏幕、字符流与电子元件、最终固定终端。这次明确纠正优先于附件中的旧布局约束，也优先于先前围绕飞机和太空作出的视觉解释。参考项目提供 CRT 与三维表现方向，不决定本站主题。
- 将交互分成片头和终端两个阶段：片头滚轮、触屏及键盘控制固定视口内的三维进度，网页没有自然滚动；终端只按屏分页。DOS 结束后停在介绍画面，旅程不自行继续。用户抵达终端前可反向探索，抵达后用 `reboot` 重演 DOS。
- 使用本站原创复古电脑、键盘、电子元件和 Canvas 生成纹理，机身标记 HADESD，不使用 Apple 品牌资产或复制参考模型。元件包括电容、贴片电阻、微控制器与小 PCB，当前活动场景移除飞机和星空。DOS 日志和分段进度只表示视觉时间线，不冒充硬件或服务诊断。
- 保留始终可达的跳过入口；减少动态效果、Off 与 GPU 失败直接进入终端。隐藏终端挂载后暂设为 inert，进入终端再允许输入；SSR / 无 JavaScript 正文不受该隐藏状态影响。手机继续仅在用户点击后聚焦。
- 延续 `hadesd.display.v2` 中已经保存的显示偏好，不因场景升级再次覆盖用户选择。Three / R3F / WebGPU / WebGL2 / TSL 主管线、原生语义、独立内容 URL、静态发布与 Reactive 后端保持既有契约。
- 将原 v2 公开站说明逐字节归档为 `web-v2-notes.md`。v2 的 52 条单测、14 项 E2E 和 16 项性能检查仅保留为历史；v3 的通过状态必须来自本轮实际运行，不能沿用历史数字或把预计测试数量写为已通过。

## 2026-09-09：80% 暂停、续启与逐批终端（v4）

- 按用户进一步明确的动画节奏，将开机拆成连续八阶段：先在同一块 CRT 加载到 80%，拉远显露电脑，等待滚动；旅程结束后回到 DOS 续载至 100%，穿屏，再分批建立终端。v3 的开机直接到 100% 和旅程结束立即 ready 不再适用。
- 时间驱动与用户驱动分别建模：只有 boot / pullback / resume / penetrate / reveal 有定时进度，hero 与 journey 由用户推进。旅程 100% 仅启动 resume，ready 必须等待 terminal，不能用同一个完成标记提前释放命令输入。
- 七批显示作用于真实 DOM visibility，同时保留完整布局和输入值；捕获根属性变化让 GPU 读取同样的显示状态。每批间隔在 190–260ms 内随机，末组后保留 100ms，再解除 inert。跳过、Off、减少动态效果或 GPU 故障一次性显示所有组；SSR 不设置客户端显示门控。
- 电脑提示符、原创笑脸 ASCII 映射、弯曲屏幕与真实电子元件继续服务于个人计算机主题。DOS 进度与日志仍是视觉叙事，不冒充设备或后端诊断。依赖版本、用户显示偏好、公开数据、后台与非阻塞架构不因此改变。
- v3 说明完整归档为 `web-v3-notes.md`，60 条单测、16 项 E2E、16 项性能检查与 544.71 KiB 全部保留为历史。v4 验收必须重新记录，不用尚未执行的计划测试替代实际结果。

## 2026-09-09：ASCII 明暗与滚屏接缝（v4.1）

- 本轮用户纠正限定在 ASCII 过渡：暗色 Mac Face、亮色字符背景、接近 Skyworks 的逐格滚动，以及相邻 tile 不暴露非预期底色。八阶段时间线、固定终端、公开业务、后台和 Reactive 架构继续沿用。
- 屏幕 TSL 变形与轮换直接适配 Skyworks 的 CylinderPlane 和对应旅程逻辑，明确记录原算法来源；此前“场景与 shader 自主实现”只描述 v4 历史，不能作为本轮滚屏原创声明。本站生成的电脑 / 元件模型、Mac Face 与 DOS 内容继续单独记录来源。
- 屏幕采用不透明深度遮挡，圆角边界写黑色而非透明孔；第一张屏幕也不透明，物理 Mac 与首格在同一帧互斥切换，后段不整体淡出。格子以约 20 物理像素为基础，手机保留至少 48 列 / 40 行；黑色圆角分隔属于参考设计，需要消除的是分隔处出现非预期工作台或背面颜色。
- 用户指出 Mac 屏幕到滚筒的 Face 比例突变后，改为共享 27.5% 交接点和物理屏幕到视口 UV 的映射；双方使用同一个 Face 采样函数，镜头 / 旋转 / 曲率从相同进度开始。新增源图比例与交接 UV 一致性的几何不变量测试，实际图形使用 `asciiTilesVisible` 区分 Mac 上的 ASCII 与滚筒首格，避免用透明叠化或整数进度掩盖不连续。
- 保留原有 17 项 E2E，在已有桌面旅程中加入停留、反向和返回同一位置的真实输入检查，不为低影响颜色改动编写复制实现常量的单元测试。明暗关系、逐格效果与接缝须由实际 WebGL2 / WebGPU 画面核对；只读状态字段不能替代像素视觉证据。
- v4 的正式报告与性能数字保留原版本含义。v4.1 的发布版本、运行结果和截图按独立原始报告记录，不以计划或旧版数字替代验收结果。

- v4.1 实际原始录屏发现穿屏后的 DOS 短暂回闪，保留原片并修复时钟状态来源。渲染帧改用 Stage 共享的 `phaseState` 引用，与 `phaseProgress` 同步读取；不再将 React 上一阶段的 prop 和已经重置的进度组合。回归测试专门在 React 提交前检验该交接窗口，生产视频另行重录，不用剪辑掩盖故障。
