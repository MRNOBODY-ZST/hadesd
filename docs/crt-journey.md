# CRT 显像与滚动旅程（v9）

v9 使用经典 Macintosh 128K 风格的立式机身、分体键盘和鼠标，保留暖白宋体标题、细粒度滚动、世界空间薄雾和移除显式浅色描边的 CRT。桌面左侧是「让想象，接通现实。」，下方紧接「滚动进入这台电脑」与细长下箭头，右侧展示经典电脑；手机保持标题在上、电脑在下。页面仍只保留 HADESD、主标语和滚动提示。鼠标滚轮、触屏上划及键盘翻页都按较小步幅推进；没有跳过或直接进入终端按钮。减少动态效果、CRT Off 和图形故障仍直接提供可操作的终端。

## 经典电脑与接地

`RetroMac.tsx` 使用紧凑的立式浅色机身、内嵌 CRT、独立键盘和单键鼠标。物理几何包含 12,988 个三角面；模型共 23 次绘制，包含屏幕和两张贴花，反射与全场景后处理另计。重复键帽、通风口和其他同材质部件合并绘制。组件释放自有几何、材质、铭牌及键盘字符纹理；共享屏幕材质由场景管理，不随模型卸载重复释放。

机身保持水平，只绕 Y 轴偏航，指针带来很小的左右响应。`computerLens` 在介绍包络内把视场角从 44° 温和展开到 52°，相机距离由 `11 × tan(22°) / tan(fov / 2)` 同步补偿。相机 Y 高度按同一包络升至桌面 1.25、手机 1.05，并始终看向原点；介绍偏航基准分别为 −0.65 和 −0.38 弧度。靠近首格时，镜头回到原来的 44°、距离 11 和 Y=0，继续沿既有滚筒相机轨迹运动；机身偏航也随包络归零。从 hero 进入 journey 时，主灯随进度平滑变化，避免阶段切换造成跳亮。

`computerGeometry.ts` 导出的完整物理包围盒为 `min=[-1.9170264,-2.375,-1.01]`、`max=[2.22354794,2.20,2.06301213]`。主机支脚、键盘和鼠标的最低点对齐 `RETRO_COMPUTER_FLOOR_Y=-2.375`；`computerGroundHeight` 再按包围盒、四元数、统一缩放与世界 Y 计算实际地面位置，并留出很小的间隔以避免深度冲突。三组 `RETRO_GROUND_FOOTPRINTS` 分别包住主机、键盘和鼠标，接触阴影与雾气避让共用这些有方向的占地范围。回归已核对全部部件高于支撑面、三者最低点一致、真实顶点位于对应占地范围内、屏幕开口无遮挡和资源释放。

物理屏幕与滚筒通过共享的 `RETRO_MAC_SCREEN` 和投影计算对齐：中心为 `[0,0.65,1.06]`，宽 2.7、高 2.05，边界为 `left=-1.35`、`right=1.35`、`bottom=-0.375`、`top=1.675`。几何回归保留这一交接契约，屏幕开口、材质 UV 与首格切平面保持对应。

## 过场

`boot → pullback → hero → journey → resume → penetrate → reveal → terminal`

初次开机总长五秒，阶段由 `timeline.ts` 统一计算：

| 阶段 | 时长 | 画面 |
| --- | --- | --- |
| CRT 预热 | 350 毫秒 | 首个 GPU 提交帧之后保持黑场，可有极弱宽面反射，无文字、进度条或发白轮廓 |
| DOS | 1.6 秒 | 启动日志逐行输出并滚屏 |
| 显示模式切换 | 180 毫秒 | DOS 退出，切换到图形界面 |
| 图形界面加载 | 2.87 秒 | 状态行依次出现，分段进度条与数字百分比从 0% 到 80% |

启动到 80% 后，镜头用约 1.8 秒带着径向残影拉出电脑。物理 CRT 的启动界面、终端演示和 ASCII 图标都经过同一层镜片，保持曲率、扫描线与色散，屏幕边缘直接过渡到黑色。经典主机与外设落在柔和的接触阴影上，地面保留模糊的真实屏幕反射，暖灰与淡紫薄雾在世界空间中缓慢流动。

滚动先靠近同一块屏幕，在旅程 27.5% 处与滚筒首格使用相同 UV 和切平面交接。五列滚筒的每个常规格都保留可识别的 Mac 图标，仅图标之外的背景字符随机变化；最终交接格仍显示 DOS／图形启动画面。前景为有深度与指针视差的 0101 字符串。最终格展平后，同一图形界面约 1.3 秒从 80% 续载至 100%，状态行和百分比继续更新。镜头随后用约 1.1 秒单向穿入屏幕，取消此前的挤压收束和故障闪动；七批终端内容依次建立，最后允许终端输入。

桌面与手机使用同一时间线，启动画面按共享布局适应视口。初次开机与 `reboot` 都从黑色 CRT 阶段开始；进入续启后不能再反向滚回介绍。片头日志、状态与进度描述视觉序列，不代表真实硬件检测或网络下载。

## 屏幕演示与图标

电脑屏幕提供八种预设：命令提示符、Python 整数平方、ANSI 色彩、Python 正弦波、Python 二进制、Python 矩阵乘法、Python 帕斯卡三角和 Mac 图标。先显示命令提示符，其余七种随机排序；每种占八秒，文字在前 5.5 秒内逐步显现。演示时钟只在屏幕可见时推进。Python 示例是可独立运行的代码，预设输出与代码对应；浏览器在此播放预制演示，不连接服务器 Shell，也不启动 Python 解释器。

物理屏幕和全部滚筒图标使用共享的 `face.sampleColor(uv, seed)`：轮廓、双眼与笑脸按像素镜像，双眼同步眨动，采样在网格量化前折叠坐标，避免字符网格再次引入左右偏差。种子只影响图标外的背景。背景使用随时间变化的亮度场选择字符图集，保留 [Skyworks ASCII 背景的采样思路](https://github.com/shader-sweden/skyworks/blob/2eb7ad3b4b861cbfc17adebff5e9fa8c861babeb/src/components/asci-background.tsx)，本站以程序化亮度场驱动，不依赖背景视频。首格与物理屏幕保持相同采样，末格继续复用启动材质，避免交接时图像跳变。

## 终端显示与交互

终端显示区域占视口的 98% 宽、96% 高，内部保留文本边距和移动设备安全区。`contentRect` 从真实 DOM 边界计算；GPU 在全屏平面中按该区域采样文字，进入可操作阶段后不再对内容做偏移点击位置的曲面变形。链接、文本选择、表单、Vim 和分页仍由真实 DOM 处理，显示区域与命中坐标对应。

v9 保留 v8 的去白圈改动：移除 `crtSignal.sheen`、最终终端材质的轮廓高光、CSS 装饰框和整页 CRT 覆盖层的 1px 浅色内边线。启动备用画面也不再绘制边线或蓝白高光圈；保留圆润黑色裁切、扫描线、RGB 色散、暗角与极弱宽面反射。终端背板使用纯黑 MeshBasicMaterial，不参与灯光反射，避免暗色材质在圆角擦边产生高光细线。渲染器以纯黑清屏，`worldAlpha` 统一控制场景背景、地面、反射和世界雾的出现与退场：拉出电脑时展开，进入首格时淡去，滚筒中段恢复，末段再次退至零。开机、续载、穿屏、内容揭示与最终终端等满屏 CRT 画面使用黑色外部背景，场景地面不延伸到画面外围。

终端仍按屏分页，长表单增加屏间重叠，确保控件可在一屏完整操作。账号、搜索、设置和评论操作在终端内展开，Vim 的管理员草稿保存与普通读者本地副本语义保持不变。完整操作见 [README](../README.md#开机探索与终端操作)，博客及 MinIO 说明分别见 [blog.md](blog.md) 与 [minio.md](minio.md)。

## GPU 与维护边界

- `Atmosphere.tsx` 与 `atmosphereResources.ts` 使用 [Three ReflectorNode](https://threejs.org/docs/pages/ReflectorNode.html) 的虚拟相机重绘实际场景，共用物理电脑的动态屏幕材质与动画状态，不额外向地面投射一张屏幕图片。反射贡献系数为 0.085，采样 LOD 为 3.5；桌面 Full 的分辨率系数为 0.4，手机 Full 为 0.3，Low 为 0.25。启用 mipmap，禁止递归反射。真实反射经过柔化，与哑光地面融合；显隐服从 `worldAlpha`，在进入满屏续载之前退场，避免终端外残留地面倒影。
- `atmosphereVolume.ts` 使用两个世界空间 raymarch box，分别承载近地薄雾和机身后方雾层。每步计算三个频段的 `noise3`，通过三维坐标扰动和缓慢漂移形成有深度的密度变化，不再把屏幕空间二维噪声铺成云带。相机与反射相机分别沿各自的真实视线穿过体积，按光学深度累积颜色和透射率。Full 的桌面／手机每条射线分别最多 16／10 步，Low 分别为 8／6 步；这些是采样配置，不是实测性能数字。
- 两个雾体积使用同一节点材质工厂，共享时钟和场景淡出 uniform，在现有场景与反射中绘制，不新增离屏 pass、Canvas 或逐帧纹理上传。体积参与深度测试、不写深度，并为机壳及键盘占地留出间隙。地面同样不写深度，接触阴影随机身姿态变化；远背景只提供暗色基底，可见云团来自世界雾体积。
- 滚筒保留五列各 16 格，但使用 4 次几何绘制、5,120 个三角形；二进制流使用一次实例化绘制。完整场景还有模型、反射和后处理，不能把这些数字当成整帧总量。圆柱变形保留 [Skyworks 来源](https://github.com/shader-sweden/skyworks/blob/2eb7ad3b4b861cbfc17adebff5e9fa8c861babeb/src/components/scenes/hero/cylinder-plane.tsx)。
- 字符随机变化、演示文字显现、图形进度条与百分比、指针波纹、薄雾和光效通过 uniform 与 GPU 节点更新。预设文字、图标与数字预先绘入共享图集，不逐帧重新上传字符图片。终端正文只在必要变化时重画文字纹理。
- Full 的片头目标上限为 120 管线帧/秒，终端为 60；Low 片头为 30，终端按需更新。实际帧率受刷新率、GPU、视口和系统负载影响。主画布按桌面 2.3MP、手机 0.9MP 预算计算像素比；文字纹理和反射等辅助目标另计。
- `fiberRendererClock.ts` 针对固定的 Three 0.186.0：在非 XR、无用户动画回调且内部接口匹配时停止重复的 Three 计时循环，由 Fiber 在实际提交帧前推进节点时钟。反射等 FRAME 节点每帧更新一次。接口不匹配时保留原有调度；升级 Three 必须复核此适配层。减少动态效果与 Off 不持续进行无意义的 RAF 调度。

性能测量脚本记录实际后端、适配器、管线提交帧、draw calls、三角形、纹理重画和 RAF 回调。`renderCpuMs` 是 CPU 提交耗时，不是 GPU 耗时或 GPU 利用率；提高利用效率不等于持续占满显卡。测试口径与历史数字见 [性能文档](performance.md)，v9 不能直接沿用旧模型的测试或实测数据。
