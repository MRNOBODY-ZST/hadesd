## 已验证行为

- `open`、`vim`、`less` 在终端内打开源码；NORMAL、INSERT、COMMAND 模式，`:w`、`:wq`、`:q`、`:q!`、`:x`，未保存退出保护和失败保留。
- 管理员保存真实私有修订，保留元数据并检查版本冲突；已发布内容保持独立。退出登录或切换账号后，私人草稿立即从界面隐藏并锁定。
- 普通读者编辑明确标注的浏览器本地副本。中文输入法、命令补全、历史、正文分页和表单键盘操作分别处理。
- 登录、注册、资料、文件、评论、搜索和显示设置在终端内操作；桌面与手机没有横向溢出或弹窗覆盖。评论可用 `:wq` 提交。
- 真实 MinIO 上传、下载、删除与附件权限；修订、历史版本发布、草稿与搜索隔离、撤稿、回滚、评论回复及附件权限。
- MinIO 私有桶初始化可重复执行。可选本机 overlay 的回环健康检查返回 HTTP 200，验证后恢复为无宿主机端口的私有服务。
- 从真实 MinIO 导出数据库引用对象：`examined=1, copied=1, pending=0, bytes=37`，大小与 SHA-256 校验通过。以导出目录反向预检：`alreadyPresent=1, pending=0`，证明现有目标一致且可重复运行。
- 生产备份脚本副本仅将固定路径改为 QA 路径，在隔离环境完成数据库转储、发布目录、私有配置和真实 S3 导出，校验成功后生成 `COMPLETE`。运行中与配置中的存储不一致、导出失败时会拒绝成功；没有运行生产备份或恢复生产数据。

Windows 的 publisher 符号链接测试受权限限制，因此完整工作区单测在远程 Linux 运行。Java 本轮执行上述 14 项测试，未执行完整 Testcontainers 套件；真实存储行为由独立 MinIO 环境联调补充验证。构建仍有既有大文件分块提示，部分测试有 React act 环境提示，均未导致失败。

管理员发布 E2E 和 API 生命周期脚本需要显式设置 `HADESD_ISOLATED_TEST=true`，并使用隔离环境的账号与数据库。它们会创建修订和临时发布，再恢复公开基线；不得对真实生产站运行。

远程无法直接拉取 Docker Hub 和 Go 依赖，因此 QA 的 MinIO 二进制在本机按仓库固定上游模块交叉编译、校验后上传，使用远程已有基础镜像组装；这是 QA 构建，不是官方预构建镜像。正式构建方式、配置和迁移顺序见 [MinIO 文档](minio.md)。

使用方式见 [博客与终端交互](blog.md)。历史验收记录保留原日期和范围，不代表本轮重新执行了所有历史测试。
