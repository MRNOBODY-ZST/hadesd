## 02. 不可改变的产品原则

1. 外观是复古终端，内容体验是现代博客；不要求访客学习命令。
2. 所有核心公开功能同时支持鼠标和命令，两者共用业务操作与路由。
3. 正文、链接、按钮和输入框使用真实 DOM；WebGL 负责 CRT 氛围，不承载整篇正文。
4. 终端是浏览器内的只读博客命令系统，不是真实 Shell，不连接服务器终端。
5. 直接打开文章链接就能阅读，不先播放开机动画，不要求重新输入命令。
6. 无 WebGL 仍能完整浏览；无 JavaScript 仍能阅读预渲染正文并通过普通链接访问公开栏目。
7. 后台必须真实持久化。刷新页面、重启应用后，文章与设置不能丢失。
8. 单作者、公开阅读、私有管理后台。第一版不做公众注册、评论社区和多租户。
9. 中文界面，中英混排正文；命令、路径和技术标识保留英文。
10. 不编造 Hades 的真实姓名、学校、任职、论文、获奖、联系方式或访问数据。

默认不加入聊天机器人、AI 自动写作、真实远程终端、支付、复杂权限平台、微服务、Kafka、Elasticsearch 或 Kubernetes。

## 03. 固定技术方向

前端选 React，不同时实现 Vue，也不要擅自切换 Next.js。

公开站点：React + TypeScript strict + React Router Framework Mode + Vite，使用静态预渲染。构建时需要 Node.js，公开站点运行时不依赖 Node SSR 服务。

管理后台：独立的 React + TypeScript + Vite SPA，部署在同域 `/admin/`。它与公开站点共享类型、Markdown 渲染和必要的 UI 基础组件，但其代码不要进入公开首页首屏包。

状态与请求：Zustand 管理界面状态；TanStack Query 管理后台服务端状态及必要的动态查询。URL 是文章、栏目、标签和可分享搜索条件的权威来源。

样式：CSS Modules + 全局 CSS Variables 设计令牌。不要同时引入多套 CSS 框架。可访问性复杂的弹层可采用轻量 Headless 组件，但避免整套重型后台组件库进入公开站点。

内容：Markdown，使用统一渲染包；支持 GFM、代码块、目录、数学公式。优先采用 react-markdown 生态；不允许内容执行任意 MDX/JavaScript。

特效：原生 WebGL2 + GLSL，封装独立 CRT 渲染器。第一版不需要 Three.js，不需要 xterm.js，也不使用 html2canvas 周期性截图来伪造整屏 CRT。

后端：Java 21 + Spring Boot 4.x 稳定分支 + Spring MVC + Spring Security + Spring Data JPA + Bean Validation + Flyway + Maven Wrapper。

存储：MySQL 8.4 系列保存事实数据；Redis 保存管理员 Session、限流状态与可重建缓存；附件通过 StoragePort 接入存储。

文件存储：开发环境提供真实的本地文件适配器并使用持久化目录；生产支持 S3 兼容存储适配器。两者使用同一业务接口，本地模式不是假上传。

搜索：第一版使用 MySQL FULLTEXT + ngram，并提供明确的短查询策略。定义 SearchPort 为后续搜索引擎替换留边界，但不要提前部署 Meilisearch。

测试：前端 Vitest + Testing Library，端到端 Playwright；后端 JUnit + Spring 集成测试 + Testcontainers，数据库测试使用真实 MySQL 行为，不以 H2 代替全文索引和事务测试。

部署：Docker Compose + Nginx；提供独立的可信发布 Worker，执行固定的静态构建及切换流程。Worker 可以使用 Node.js，但不是一个 Node SSR 网站服务。

开始实施时核查各组件的稳定版本与兼容性，将准确版本写入 lockfile、Maven 和部署配置。不使用 `latest`、SNAPSHOT、预览版或猜测的补丁版本。

## 07. 页面与鼠标体验

公开页面必须包括：

- `/`：简介、最近文章、精选项目、主要入口。
- `/posts` 与 `/posts/:slug`：文章目录与文章阅读。
- `/projects` 与 `/projects/:slug`：项目目录与项目详情。
- `/research` 与 `/research/:slug`：研究记录；不编造论文与指标。
- `/about`、`/now`、`/links`：关于、近况与配置的外部链接。
- `/tags/:tag`：标签内容。
- `/search?q=...`：公开内容搜索。
- 真实 404 页面。

内容为空时展示有设计的真实空状态，不伪造文章、项目或成果数量。

文件夹、文章、标签和面包屑均可点击。文件和文章使用真实 `<a href>`，保留复制链接、新标签页打开和浏览器后退/前进。

鼠标点击直接执行内容操作，不先模拟逐字输入命令。可以在终端历史中附加一条简短操作记录，但不得延迟导航或重复打开。

设置提供主题、CRT、阅读模式；阅读模式减少边框、隐藏目录和终端干扰，保留返回完整界面的入口。

实现命令面板，支持 Ctrl/Cmd+K 打开，搜索导航操作和文章。它与终端、鼠标使用同一组动作。不要让快捷键在其他编辑器内误触发。

## 08. 阅读器

文章必须有独立标题、发布时间、更新时间、摘要、标签、目录、正文、永久链接与上一篇/下一篇；不存在的数据不显示占位值。

正文支持标题、列表、引用、表格、脚注、图片、链接、代码和数学公式。长代码块独立横向滚动并可复制；不让整页横向滚动。图片保留 alt，已知尺寸时预留空间。

文章内容使用语义化 `<article>`、合理 heading 层级和真实锚点。长文章目录根据标题生成，刷新带 hash 的链接仍能定位。

文章展开后，终端历史收进可展开面板，正文成为主要阅读区。`cat` 不承担全文阅读器职责。

提供打印样式：移除终端、目录和 CRT，保留标题、正文与必要链接。

Markdown 的发布渲染、管理预览和示例展示共享同一配置。禁止原始 HTML、脚本 URL、任意 iframe 与可执行 MDX。数学渲染关闭信任模式；插件输出和自定义链接渲染都必须经过安全检查。

不要直接把后端返回的字符串交给未经校验的 `dangerouslySetInnerHTML`。代码高亮避免将整个语言库塞进首屏，支持按需加载或构建时处理。

## 09. 虚拟文件系统

VFS 仅由当前已上线内容快照生成，不读取服务器目录，也不映射对象存储桶。

```text
~/
├── posts/
│   └── building-hadesd.md
├── projects/
├── research/
├── about.md
├── now.md
└── links.json
```

内部根路径统一为 `/`，UI 显示为 `~`。例如 `/posts` 显示 `~/posts`，对应真实路由 `/posts`。

文件节点包含稳定内容 ID、类型、虚拟路径、公开路由、标题、摘要、修改时间和公开标签。节点中不得出现草稿 ID、后台地址、存储凭据或服务器路径。

路径解析支持绝对路径、相对路径、`~`、`.`、`..`、重复斜杠和尾部斜杠；到根目录后再 `..` 仍停留根目录。

文件名使用稳定 slug；中文标题作为展示名。跳转由内容 ID/路由映射完成，不直接拼接原始用户输入到网络地址。

目录状态随路由变化同步。浏览器后退/前进、点击目录和执行 `cd` 不得出现三个不同的当前位置。

## 10. 命令系统：完整第一版范围

命令提示符示例：`guest@hadesd:~/posts$`。

实现下列命令；帮助、补全与命令面板尽量从同一个命令注册表生成：

| 命令 | 语义 |
| --- | --- |
| `help [command]` | 显示所有命令或单个命令的参数和示例 |
| `ls [-l] [path]` | 列出目录；长格式包含内容类型、修改日期 |
| `cd [path]` | 切换目录；无参数回到根目录；支持 `..` |
| `pwd` | 输出规范化的当前 VFS 路径 |
| `tree [path]` | 显示当前公开目录树 |
| `cat <file>` | 输出短文本；过长时截断并给出打开全文链接 |
| `open <file>` | 打开完整阅读器或允许的内部页面 |
| `less <file>` | `open` 的阅读器别名，不实现真实分页终端 |
| `search <query>` | 搜索公开内容；支持引号内空格 |
| `tag <name>` | 打开标签结果 |
| `about` / `projects` / `research` / `now` | 常用栏目快捷入口 |
| `history` / `history --clear` | 查看或清理命令历史 |
| `clear` | 仅清空输出记录，不清空文章、输入历史或服务端数据 |
| `theme amber\|green\|paper` | 修改本地主题 |
| `crt off\|low\|full` | 修改本地效果档位 |
| `reader on\|off` | 开关阅读模式 |
| `hadesctl status` | 显示站点公开版本与本地状态，不显示真实服务器遥测 |
| `hadesctl projects` / `hadesctl now` | 对已有功能的别名 |

解析器使用 tokenizer + 命令注册表，不用 `eval`、动态函数和真实 Shell。支持单引号、双引号和文档化的转义规则。未闭合引号必须友好报错。

第一版不支持管道、命令替换、重定向、分号串联和任意系统命令。引号外出现这些语法时提示不支持；引号内的搜索文本按普通字符串处理，绝不执行。

例如 `search "C++ && Rust"` 是普通文本搜索；`ls; rm -rf /` 不得拆开执行，也不能传给后端进程。

输出使用结构化类型，例如 `text`、`directory-list`、`search-results`、`help`、`error`、`navigation`。结果通过 React 组件渲染，不拼 HTML 字符串。

未知命令应提供相近命令和可点击帮助。`open` 只接受 VFS 文件/允许的内部目标，不充当任意 URL 请求器。

输入交互必须包含：

- 上下方向键历史；当前未提交文本可恢复。
- 补全命令与路径；匹配项可鼠标点击。
- Ctrl+Space 打开补全菜单；菜单展开时 Tab 可选中补全，Esc 关闭。普通 Tab 可以离开终端，不能造成键盘陷阱。
- 可选的经典 Tab 补全设置必须说明离开方式，不抢占全站 Tab。
- 中文 IME composing 时 Enter 只选词，不提交命令。
- 多行粘贴不自动执行；显示可编辑内容，明确提交后才处理。
- 异步命令支持取消；Ctrl+C 只在终端聚焦、存在运行任务且没有选中文字时取消该任务。
- 不拦截页面复制和其他输入框快捷键。
- 使用 AbortController 与请求序号避免旧搜索覆盖新搜索。
- 历史默认仅保留当前会话，最多 100 条；不上传命令记录作为统计。
- `cat` 最多显示 200 行或 10,000 个字符，提供打开全文入口。

所有输入、点击和命令面板最终调用同一内容动作层。写测试证明三种入口打开相同的 URL、内容 ID 和目录状态。

## 11. WebGL CRT：真实实现但不牺牲阅读

必须存在真正的 WebGL2 Canvas、GLSL Shader、初始化/销毁逻辑与效果档位。不能只用 CSS 扫描线后宣称完成了 WebGL。

层级：

```text
CRT Canvas：扫描线、噪点、玻璃暗角与轻微光学氛围
语义化 DOM：文字、链接、输入框、目录、正文
背景层：屏幕底色、边框与内凹玻璃边缘
```

Canvas 设置 `pointer-events: none`、`aria-hidden`，不参与焦点和命中测试。正确配置透明背景与 alpha 合成，不能覆盖成一整块黑屏。

不要声称 Shader 可以直接采样任意 DOM。正文不做真实桶形畸变、逐字拖影和 RGB 分离；曲面感由玻璃边缘、暗角与独立特效层表达。命令提示符可以有极弱 CSS 荧光，长文正文不得模糊。

三个档位：

- Off：停止并释放不需要的 WebGL 资源，保留正常页面。
- Low，默认：静态细扫描线、轻微暗角；仅初始化、尺寸或设置变化时绘制，闲置时不运行永久动画循环。
- Full：增加低强度动态噪声和极短的界面过渡，帧率上限 30fps；不做全屏高对比闪烁。

性能和生命周期要求：

- DPR 默认上限 1.5，缓冲区设置合理像素上限，初始按约 200 万像素预算实现。
- 页面不可见、CRT 关闭或组件卸载时停止绘制。
- 使用 ResizeObserver，正确处理尺寸变化并清理监听器。
- Shader 失败、WebGL 不可用或 context lost 时降级为普通界面；不让页面崩溃。
- `prefers-reduced-motion` 下关闭动态效果与非必要光标闪烁。
- `prefers-contrast`、强制颜色模式和打印场景关闭 CRT 干扰。
- WebGL 每帧状态保存在 renderer 内部或 ref，不让整个 React 应用逐帧重渲染。
- React StrictMode 下重复挂载不产生多个 RAF、Canvas 或事件监听器。

效果设置放在统一配置对象中，Shader 参数有上下限。为测试提供确定性噪声 seed 或冻结时间模式，避免视觉测试随机失败。

## 12. 移动端与可访问性

小于约 768px 使用单列；目录收进抽屉；命令区默认折叠为“打开终端”按钮。不要自动聚焦导致手机键盘弹起。

不强制横屏，不要求双击或拖拽才能打开内容。处理安全区和软键盘，避免命令栏遮住输入与正文。

触控目标尽量达到 44×44px；提供可见键盘焦点、跳转正文链接、弹层焦点管理与关闭后焦点恢复。

鼠标、触屏和键盘均可完成导航。链接和按钮语义正确，不把 div 假装成按钮。

读屏提示仅播报简短命令结果或状态，不将整篇文章设置成不断更新的 aria-live。

至少验证 1440×900、1024×768、390×844、320×568 四种视口。长标题、长 URL、代码块和目录深层节点不得造成整页溢出。

## 13. 内容模型与数据库

所有事实数据使用 MySQL；Redis 不是文章或发布任务的唯一存储。

设计至少覆盖：

- `contents`：稳定 ID、类型、最新编辑修订引用、创建时间和乐观锁版本。
- `content_revisions`：不可变 Markdown 与元数据快照；标题、slug、摘要、封面、标签、语言等必须随修订保存。
- `tags` 与修订关联：不能修改全局标签后意外改变旧发布快照。
- `media`：存储键、原文件名、实际 MIME、大小、校验信息、状态及引用关系。
- `releases`：站点发布版本和快照信息。
- `release_entries`：每个版本选择的内容 ID、revision ID、公开路径。
- `publish_jobs`：构建/发布任务、状态、尝试次数、租约、错误摘要。
- `search_documents`：按 release ID 保存仅针对公开候选内容的检索投影。
- `admin_users`、`site_settings`、`audit_logs`。

最关键的边界：最新编辑修订 ≠ 已上线修订。在线内容由当前已激活 release 的 entries 决定，不由 `latest_revision_id` 决定。

slug 和正文等公开元数据不能通过修改草稿立即影响线上。slug 冲突按实际路由范围校验；同一 release 内不得存在相同公开路径。

编辑请求使用版本字段进行乐观并发控制，冲突返回 409 和明确提示，不能静默覆盖另一个标签页的修改。

Flyway 管理 schema，生产配置禁止 `ddl-auto=update`。设置必要索引、唯一约束和外键；时间统一存 UTC，API 使用 ISO 8601。ID 在前端使用字符串，避免 Java Long 到 JS Number 的精度问题。

## 14. API 契约

API 前缀统一为 `/api/v1`。先维护 OpenAPI 契约，再生成或校验前端类型，避免各端自行猜测字段。

```text
GET /public/contents/{id}
GET /public/tags
GET /public/search?q=...&page=...&size=...&releaseId=...
```

鉴权及后台接口至少覆盖：

```text
GET    /auth/csrf
POST   /auth/login
POST   /auth/logout
GET    /auth/me
GET    /admin/contents
POST   /admin/contents
GET    /admin/contents/{id}
```

发布 Worker 的任务领取、快照导出和状态回报接口归入独立 internal 命名空间，只允许受控网络和专用凭据访问；不能借用匿名 public API 输出待发布草稿。

错误使用统一 Problem Details 风格，包含稳定业务 code 与 requestId；不返回堆栈、SQL、凭据或内部绝对路径。

公开接口只返回当前可公开的字段与 release 数据。客户端带过期 releaseId 时返回明确的 `RELEASE_CHANGED`，提示刷新内容，不返回历史撤稿内容。

## 15. 搜索、缓存与故障处理

MySQL 搜索投影保存 title、summary、plainText、tags 与 releaseId，使用 FULLTEXT WITH PARSER ngram，并明确配置 ngram_token_size。

不得直接把用户字符串拼接到 SQL 或 Boolean Search 语法。定义并测试单个汉字、英文短词、C++、IP 地址、大小写、引号、空查询和标点的行为。

对短于有效 token 的查询使用有边界的标题/标签匹配策略；避免对所有正文执行无上限 `%keyword%` 扫描。结果支持分页，顺序确定。

全文搜索结果只能来自当前在线 release。错误提示、搜索摘要、数量统计和缓存都不能泄露草稿。

Redis 缓存键带 releaseId，缓存仅用于可重建的公开数据。发布切换后自然进入新 key 空间，旧缓存按 TTL 清理。设置合理 TTL 与短期负缓存，防止无限缓存不存在的资源。

Redis 不可用时，公开查询可以受限地回源 MySQL；管理员 Session 无法验证时必须拒绝访问，不得 fail-open。MySQL 不可用时，已部署的静态正文仍能阅读；动态搜索返回清晰的暂不可用状态。

搜索高亮用受控文本片段和 React 元素，不接收搜索引擎返回的任意 HTML。

## 16. 后台 CMS 与文件存储

后台是清晰、高效的现代编辑界面，不强制模拟终端或 Vim。

必须支持登录、内容列表、创建与编辑、Markdown 预览、自动保存状态、修订历史、恢复修订、标签、媒体上传、发布任务状态和站点设置。

自动保存做 debounce，但保留“立即保存”按钮。清晰区分“未保存”“保存中”“已保存”“冲突”“发布中”“已上线”“失败”。离开未保存页面时提供保护。

恢复历史修订应创建新的编辑修订，不篡改历史。发布失败时显示可操作的错误摘要和重试入口，不显示误导性的成功提示。

站点设置包含简介、首页短文案、导航与外部链接；没有配置的 GitHub、邮箱、论文链接不显示，不能填写假的个人资料。

上传第一版可经后端完成，不必引入浏览器直传。图片上限默认 10MB、PDF 上限 25MB，服务端验证实际大小和 MIME/文件特征，不仅相信扩展名。

允许 PNG、JPEG、WebP 和 PDF。拒绝 SVG、HTML、脚本、可执行文件和未经约束的压缩包。对图片限制像素尺寸，防止解码资源耗尽。

存储键由服务器生成，不采用原始文件名构造路径。本地适配器防止路径穿越；S3 适配器使用 SDK 和最小权限配置，不把 key 暴露给浏览器。

对象默认为私有。后台预览必须鉴权；`/public/media/{id}` 仅提供当前在线内容引用的媒体。PDF 按附件方式提供并设置防 MIME 嗅探头。媒体不可因“已经上传”就自动成为公开资源。

管理员不得直接删除仍被当前线上版本或保留的可回滚版本引用的媒体；错误信息说明引用来源。媒体对象不可原位覆盖，替换图片创建新对象与新引用。清理任务只删除超过保留期限且无引用的对象。新文章不依赖运行时从任意远程 URL 抓图，避免额外 SSRF 攻击面。

## 17. 预渲染与发布一致性

公开站点使用 React Router Framework Mode 的静态预渲染。显式枚举全部在线文章、项目、研究、标签和固定页面路径，不能仅设置 `prerender: true` 就假装动态路由已输出。

公开页面构建必须使用一个冻结的 release 快照，不能每生成一页就读取随时变化的最新文章列表。公开站点设置、导航和标签展示也随 release 冻结；保存后台设置不能绕过发布直接改变线上内容。

后台独立 SPA，不把管理员数据放进公开构建。React Router 关闭运行时 SSR 后，不编写依赖运行时服务的 route action/headers。

基本流程：

```text
编辑保存草稿
  → 创建指定修订版本的发布任务
  → 冻结完整 release 内容快照
  → 可信 Worker 领取任务
  → 在非公开 staging 目录构建 HTML、导航数据、RSS、sitemap
  → 校验构建产物和目标路径
  → 原子切换 current 发布指针
  → 回报状态并刷新必要缓存
```

第一版限制同时激活的发布任务为一个。任务记录持久化，领取使用事务和有过期时间的租约；失败可重试，状态变化幂等。

任务至少区分 QUEUED、BUILDING、READY、DEPLOYING、SUCCEEDED、FAILED。只有静态产物校验通过、目标 release 的搜索投影已提交、引用媒体可用后才能进入 READY。任务日志经过脱敏，不输出 token、完整环境变量和秘密路径。

本地与 Compose 部署使用共享发布卷：Worker 写入版本目录，Nginx 只读。目录名来自服务端生成的 release ID。`current` 的原子切换是上线切点。

为避免文件系统与数据库形成互相矛盾的“当前版本”，明确以已激活的 current manifest 为本部署模式的权威指针；后端通过只读发布卷读取它，并按该 release 查询公开投影。数据库中的部署状态是可核对修复的记录，不提前决定公开可见性。

Worker 崩溃在切换之后、回报之前时，应能依据 current manifest 对账恢复状态。构建失败或切换前崩溃不得改变旧站点。

首次启动没有 current 时，后台登录、编辑、任务领取和基础健康检查仍能工作；公开 release 接口返回明确的 EMPTY 状态。提供生成初始空站点 release 的受控路径，避免“必须先有站点才能发布第一个站点”的启动死锁。

不把历史 release 目录作为可访问 URL 暴露出去；保留最近少量版本用于经授权回滚。hash 命名的代码资源可独立保留以避免旧标签页加载失败，但不能把旧正文、草稿快照当成永久公共资源。

撤稿和 slug 更改需要重建对应路由、列表、标签、RSS、sitemap 与搜索。撤稿后，旧公开路径和客户端数据请求应不再返回正文。浏览器或外部平台已缓存/保存的内容不能保证追回，不要声称绝对删除。

第一版默认不缓存 HTML 到外部 CDN；若开启 CDN，应提供明确的 purge 步骤和失败处理，不将其默认为自动完成。

Worker 只运行仓库中固定、受信任的构建入口，不将命令、文章标题、slug 或 Markdown 插值到 Shell 命令。后端不得提供通用执行接口，容器不得为了构建方便挂载 Docker socket。

## 18. SEO、静态路由与安全头

为每个公开文章生成独立 title、description、canonical、Open Graph 信息。提供 RSS、sitemap.xml 和 robots.txt；不包含草稿、预览、后台和虚构作者资料。

请求文章 URL 返回包含正文的 HTML。不存在的公开路径返回 HTTP 404，不通过全局 SPA fallback 把所有不存在的文章变成 200。

Nginx 正确服务 React Router 的 HTML 和客户端导航数据产物；`/admin/*` 可以使用后台 SPA fallback，但不得影响 `/api/*` 或公开文章 404。

hash 静态资源可以长期缓存；HTML、内容数据与版本指针采用适合重新验证的策略；草稿预览与认证响应使用 `no-store`。

设置合理的 CSP、X-Content-Type-Options、Referrer-Policy 等。CSP 必须兼容实际构建与 hydration，使用可实施的 hash/nonce 策略，而不是一边阻止应用启动一边声称安全；不依赖 unsafe-eval 或宽泛通配来源。

## 19. 认证与安全边界

后台采用 Spring Security 服务端 Session + Spring Session Redis。第一版单管理员，不实现公众注册。

生产 Session Cookie 使用 HttpOnly、Secure、合适的 SameSite 与最小作用域；登录轮换 Session，退出使服务端 Session 失效。不要把认证 token 放进 localStorage。

保留 CSRF 防护，前端按当前 Spring Security 文档处理 token 获取、登录/退出后的刷新及写请求 header。不要为了让请求成功而全局关闭 CSRF。

同域部署优先；开发代理解决跨域。不使用带凭据的任意来源 CORS。登录、搜索、上传设置有边界的限流。

首次管理员通过本地 CLI/受控 bootstrap 创建，不开放匿名初始化接口，不提交固定管理员密码。密码使用 Spring Security 支持的安全哈希方案。

公开终端绝不连接 ProcessBuilder、Runtime.exec、SSH、PTY、服务器 Shell 或数据库控制台。即使输入 `sudo`、`rm`、`curl`、`ssh` 也只得到不支持的安全提示。

数据库、Redis、内部 Worker API 和管理型 Actuator 端点不得暴露公网。日志不记录密码、Cookie、CSRF 值、对象存储 key secret 或完整草稿。

对鉴权、对象级权限、Markdown XSS、SQL 注入、上传、路径穿越和草稿泄露建立具体测试。隐藏按钮或知道一个 UUID 不构成授权。

## 20. 开发、示例数据与部署

提供 `.env.example`，解释每个变量用途，但不填写真实凭据。开发初始化脚本可以生成随机本地秘密，写入 Git 忽略且权限受限的文件，不把密码打印进测试报告。

开发模式必须不依赖付费云账户即可完整验证：本地文件存储、MySQL、Redis、前后端和发布 Worker 都有可运行路径。

生产 S3 适配器在真实云凭据不存在时不得伪装成已连接。可测试其协议契约，但报告应说明是否实际联通过目标服务。

示例内容只在显式 demo/seed 模式启用，清楚标为示例。不默认发布用户并未提供的个人经历。可创建：

- “欢迎来到 hadesd.sh”示例文章。

## 21. 测试、性能与视觉验收

不要把“构建通过”当成全部验收。至少覆盖下面这些真实场景。

终端单元测试：引号和转义、未闭合引号、危险语法、Unicode、相对/绝对路径、根目录边界、未知命令、补全、历史、clear 语义、过长 cat、取消与异步竞态。

前端组件测试：IME Enter 不执行、焦点可离开终端、点击与命令使用同一动作、没有配置的外部链接不显示、空状态与错误状态可操作。

后端集成测试：匿名访问后台被拒绝、CSRF、登录退出、修订不可变、乐观锁冲突、slug 冲突、草稿无法被列表/搜索/媒体接口发现、上传类型/大小限制、当前 release 过滤。

发布测试：构建失败保留旧站、重复回报幂等、Worker 崩溃后租约恢复、切换后状态对账、撤稿路由失效、回滚、旧 releaseId 查询处理。

端到端至少完成：

1. 只用鼠标从首页进入文章，复制代码，切换阅读模式，返回目录。
2. 执行 `help → ls → cd posts → ls → open <file>`，验证 URL 和内容正确。
3. 用搜索、标签、命令面板找到同一篇文章。
4. 后台登录、创建、保存、上传图片、预览、发布、刷新前台读取实际数据。
5. 修改已发布文章但不发布，公开页面保持原样；发布后再更新。
6. 撤稿后文章、搜索、目录和公开媒体引用按规则失效。
7. 禁用 WebGL，页面正常；模拟 context lost，不黑屏。
8. 禁用 JavaScript，直接文章请求仍有可读正文与链接。
9. 手机视口通过触控路径完成浏览，不自动弹出键盘。
10. 数据库/Redis 的相关故障按规范降级或拒绝，不泄露数据。

运行真实浏览器并截图检查首页、目录、长文章、终端帮助、搜索、后台编辑器和移动端。至少检查布局、字号、颜色、焦点、滚动、遮挡、长文本和响应式。

WebGL 若在测试环境只有软件渲染，应明确记录；不能仅凭 headless 截图声称已验证真实 GPU 性能。图片生成工具不可用不应阻塞开发，以本规范作为视觉基准，禁止把静态截图当作可交互界面。

工程性能目标：公开首页必要首屏 JS gzip 尽量控制在 300KiB 内；编辑器、高亮语言包、公式和后台分包按需加载。数值是预算而非虚假保证，输出实测构建体积。

CRT Low 闲置时没有持续 RAF；Full 不超过配置帧率；无可修复的 hydration mismatch、资源泄漏或浏览器控制台错误。不要用全局 suppressHydrationWarning 或禁用 SSR 来掩盖主题、日期和客户端状态的 hydration 问题。长列表分页或按需加载，终端历史数量受限。

给出实际验证过的命令、退出状态、关键结果和报告路径。未执行的测试明确列出原因，不使用 skip/空断言掩盖功能缺失。

## 22. 推荐实施顺序

按以下顺序完成，而不是先做几十个空页面：

A. 仓库检查、依赖锁定、设计令牌、API 与共享类型、最小数据库迁移。

B. 后台鉴权、创建和保存修订、单篇内容的发布快照，建立真实持久化闭环。

C. 公开首页、目录和文章阅读器；鼠标导航、独立 URL、基础预渲染。

D. VFS、命令解析器、共享动作层、帮助/补全/历史/搜索入口。

E. WebGL CRT、主题、阅读模式、移动端和可访问性。

F. 完整 CMS、媒体、搜索、发布队列、Worker、版本切换、撤稿和回滚。

G. SEO、安全加固、故障路径、E2E、截图修正、部署与恢复验证。

每个阶段让软件处于可运行状态，更新 progress 文档。不要把第一版必要功能写成“以后实现”却报告整体完成。

若单次上下文不足，优先完成并验证当前切片，准确记录尚未完成的范围和下一条可执行任务。不要宣称会在后台继续，也不要生成假完成总结。
